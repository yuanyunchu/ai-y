# AI 驱动研发小白操作手册 v1.0

> 写给第一次用这个流程的同学 —— 按步骤来就行，不用理解所有细节

---

## 一、记住三条铁律（别违反）

1. **AI 写的东西你一定要看** —— 没你说"通过"，不保存
2. **按顺序来** —— 先调研 → 再设计 → 再写代码，别跳
3. **每一步都有产出文件** —— 下游用上游的文件，别看原始需求

---

## 二、最简单的完整流程（10 步）

假设你想做一个功能："用户登录后能看到自己的积分"

### 第 1 步：说你的想法（Explore）

**你只需要说**：
```
/opsx-explore 我想做一个功能：用户登录后能看到自己的积分
```

**然后 AI 会**：
- 问你几个问题（比如：积分从哪来？能看到什么信息？）
- 生成 `openspec/changes/user-points/proposal.md`

**你要做**：
- 回答问题
- 看 proposal.md，觉得没问题就说"确认"

---

### 第 2 步：等 AI 做设计（Propose）

**AI 自动会**（你不用操作）：
- 读取 proposal.md
- 生成技术方案 design.md
- 生成详细规格 specs/.../spec.md
- 生成任务清单 tasks.md

**你要做**：
- 看一遍 design.md，觉得靠谱就说"继续"

---

### 第 3 步：AI 写代码（Apply）

**你只需要说**：
```
/opsx-apply
```

**AI 自动会**：
- 按 tasks.md 一个一个写代码
- 同时写测试代码
- 每做完一个任务会标记 [x]

**你要做**：
- 喝杯茶，等 AI 写完

---

### 第 4 步：AI 自己检查（Quality Gate）

**AI 自动会**（你不用操作）：
- L1：检查语法、格式
- L2：检查命名、规范
- L3：检查逻辑、边界
- L4：检查测试覆盖率

**如果有问题**：
- L1 问题 AI 自己修
- L2-L4 问题 AI 会告诉你，等你决定

---

### 第 5 步：另一个 AI 评审（Code Review）

**AI 自动会**（你不用操作）：
- 找另一个模型来评审刚才写的代码
- 列出问题：严重/警告/建议

**通过标准**：
- 严重问题 = 0 才能过

---

### 第 6 步：你来审查（最重要！）

**AI 会给你看**：
- 代码摘要
- 关键修改点
- 完整内容

**你可以说**：

| 你说 | 意思 |
|-----|------|
| "通过" / "OK" | 没问题，保存 |
| "改下第 X 行" | 小修改 |
| "不对，重做" | 方向错了，重来 |
| "为什么..." | 让 AI 解释 |

**记住**：没你说"通过"，AI 不会保存任何东西

---

### 第 7 步：提交代码（Git）

**AI 自动会**（你不用操作）：
- 先同步远程代码
- 提交
- 给你看 diff
- 推送到远程

---

### 第 8 步：前后端联调（Contract Verify）

**如果有前后端**：
- 前端会自动校验接口返回的数据格式
- 有问题直接红屏提示
- 最后 AI 会跑一遍所有接口，生成报告

---

### 第 9 步：流程检查（Integration Test）

**AI 自动会**（你不用操作）：
- 检查所有文件都齐了
- 检查所有任务都做完了
- 检查 Git 历史没问题

---

### 第 10 步：归档（Archive）

**你只需要说**：
```
/opsx-archive
```

**AI 自动会**：
- 把整个 change 目录移到 archive/
- 加上日期前缀
- 告诉你归档完成

---

## 三、简化模式（赶时间用）

### 快速模式（跳过 Code Review）
```
Explore → Propose → Apply → Quality Gate → User Review → Commit
```

### 原型模式（跳过详细设计）
```
Explore → Apply → User Review → Commit
```

### 紧急修复（跳过前两步）
```
直接 Apply → User Review → Commit
```

**⚠️ 底线**：User Review（你审查）和 Git Sync Guard 不能跳过

---

## 四、常见问题

### Q：AI 写的代码有 bug 怎么办？
A：
- 还没提交 → 说"修改"或"重做"
- 已经提交 → 新建一个 change 来修 bug
- 紧急 → 可以跳过 Explore/Propose，但 commit message 要写 "hotfix"

### Q：前后端接口对不上怎么办？
A：Propose 阶段会生成 api-spec.yaml，前后端都按这个来，最后用 contract-verify 检查

### Q：用哪个模型？
A：
- 看很多代码 → Claude Sonnet 200k / Kimi
- 动脑子的活 → DeepSeek-v4-pro / o3
- 要快 → GPT-4o / Gemini Flash
- 测试 → GPT-4o-mini

|-----|------|-----------|

| `/opsx-propose` | 架构设计 | Explore 完成后 |

## 六、第一次用？按这个来

1. **先看目录结构**，认识一下这些文件夹：
   - `openspec/changes/` —— 放你正在做的功能
   - `openspec/changes/archive/` —— 放做完归档的功能
   - `project-context/` —— 放项目规范

2. **试着运行一个简单的命令**：
   ```
   /opsx-explore 我想测试一下流程，做一个 hello world 接口
   ```

3. **按 AI 提示一步步走**，体验一遍完整流程
