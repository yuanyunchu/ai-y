## 4. 状态管理架构

### 4.1 Store 模块划分

| 模块名 | 职责 | 持久化 | 说明 |
|--------|------|--------|------|
| user | 用户信息/Token | 是 | 持久化方案待确认，优先复用现有实现 |

| permission | 动态路由/权限 | 否 | 权限模型待确认，优先复用现有实现 |
| 待确认 | 待确认 | 待确认 | 接入具体项目后补充 |

### 4.2 命名规范

- 模块命名: `模块名/动作`（如 `user/setToken`、`order/setList`）
- getters 命名: `模块名 + 实体`（如 `user/token`、`order/currentOrder`）

## 5. HTTP 请求封装

### 5.1 请求拦截器

待确认：优先复用现有请求拦截逻辑，如 Token 注入、loading 控制、重复请求取消。

### 5.2 响应拦截器

待确认：优先复用现有响应拦截逻辑，如统一错误处理、401 跳转登录、业务码处理。

### 5.3 接口规范

| 规范项 | 约定 |
|--------|------|
| 基路径 | 默认参考后端全局约定 `/api/v1`，最终以项目环境配置为准 |
| 超时 | 待确认，最终以项目 request 封装为准 |
| 请求头 | Content-Type: application/json; Authorization: Bearer {token} |
| 响应体 | 与后端 Result<T> 对齐：`{ code, message, data, timestamp }` |
| 分页参数 | 与后端对齐 `{ current, size }` |
