# User Review Gate — 用户审查关卡

## 核心原则

**AI 产出的任何东西，在落地之前必须经过你审查。**

这个 skill 是一个"关卡"，不是可选项。每当你让我写代码、改配置、生成文档后，我会停在这里，展示给你看，等你指令。

---

## 触发时机

以下操作完成后**必须**进入审查关卡：

- 写/改代码文件
- 写/改配置文件
- 写/改文档（.md, .txt, etc.）
- 生成测试用例
- 修改数据库 schema
- 任何 `git add` / `git commit` 操作

**例外**：纯信息查询、只读操作、运行已有测试，不需要审查。

---

## 审查流程

### Step 1: AI 展示产出

我会以清晰的方式展示我做了什么：

**如果是代码/配置文件：**
```
## 待审查变更

📁 文件: src/services/auth.js
📝 变更类型: 新增 (new file)

--- 代码摘要 ---
• 新增函数: validateToken() — JWT token 校验
• 新增函数: refreshToken() — token 刷新逻辑
• 异常处理: 覆盖过期、无效、伪造三种情况

--- 完整代码 ---
[展示完整文件内容或关键 diff]
```

**如果是文档：**
```
## 待审查文档

📁 文件: docs/api/authentication.md
📝 变更类型: 修改 (modified)

--- 关键变更 ---
• 第 15 行: 修正了 token 过期时间的单位（秒→毫秒）
• 第 42 行: 补充了错误码 401/403 的区别说明

--- 完整内容 ---
[展示完整文档]
```

**如果是多个文件：**
```
## 待审查变更集 (共 3 个文件)

1. src/services/auth.js          — 新增
2. src/middleware/auth.js        — 修改
3. tests/auth.test.js            — 新增

是否需要逐个审查？还是看整体 diff？
```

### Step 2: 你做出决定

你有四个选项：

| 选项 | 指令 | 含义 |
|------|------|------|
| **通过** | "通过" / "approve" / "OK" / "可以" | 变更正确，直接提交/保存 |
| **修改** | "这里改一下..." / "第 X 行..." | 大体对，但需微调 |
| **重做** | "不对，应该..." / "重新来" | 方向错了，需要重写 |
| **讨论** | "为什么...?" / "这个逻辑..." | 不确定，需要解释 |

### Step 3: AI 执行

- **通过** → 保存文件 / git add / git commit（按 git-sync-guard 规范）
- **修改** → 按你的意见改，改完再次进入审查关卡
- **重做** → 废弃当前产出，从头再来
- **讨论** → 解释清楚，你确认后再决定

---

## 快速模式（可选）

如果你觉得每次都审查太繁琐，可以开启快速模式：

> "开启快速模式，只审查新增文件和删除操作"

快速模式规则（你自定义）：
- 仅修改现有文件 → 自动通过，事后看 git diff
- 新增文件 → 必须审查
- 删除文件 → 必须审查
- 改配置文件 → 必须审查
- 改核心代码 → 必须审查

随时可以说：
> "关闭快速模式，恢复全审查"

## 与现有流程的配合

```
Explore → Propose → Apply → [User Review Gate] → Commit → Archive
                              ↑
                         你在这里把关
```

**和 git-sync-guard 的关系：**
- `user-review-gate`：审查**内容**对不对
- `git-sync-guard`：审查**流程**对不对（fetch/pull/commit/push 顺序）
- 两者都要过，顺序：先内容审查 → 再 Git 流程

**和 code-review 的关系：**
- `code-review`：AI 交叉评审（红蓝对抗）
- `user-review-gate`：你的最终审批权
- 顺序：AI 自审（可选）→ 你的审查 → 提交

## 规则

1. **绝不绕过**：没有你的明确通过，不执行任何保存/提交/推送
2. **默认展示完整内容**：不偷懒只展示 diff，要展示完整上下文
3. **修改后必须再审**：任何修改都要重新进入审查关卡
4. **尊重你的时间**：展示要精炼，突出关键变更，不是复制粘贴
5. **保留历史**：如果重做，简单说明废弃了哪些内容

---

## 快捷指令

你可以用这些快捷词跳过完整句子：

| 你说 | AI 理解 |
|------|---------|
| "过" / "ok" / "行" | 通过 |
| "改下第 X 行" | 修改模式，定位到指定行 |
| "不对" / "错了" | 进入讨论/重做模式 |
| "下次再说" / "算了" | 废弃当前产出，不保存 |
| "快速过" | 开启快速模式（需确认规则） |

---

## 为什么需要这个

- **避免幻觉**：AI 可能写出看起来对但实际有 bug 的代码
- **避免越权**：AI 不应该替你决定什么可以进仓库
- **知识传递**：审查过程就是你理解代码的过程
- **质量保证**：多一双眼睛，多一道关卡
